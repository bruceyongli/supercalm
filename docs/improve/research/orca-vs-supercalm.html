Orca vs Supercalm

A full-clone code teardown of stablyai/orca — 2.74M lines read by four parallel explorations — what it means for Supercalm, and the execution plan that survived adversarial review by two fleet models.

The verdict in three sentences

Orca is the best cockpit in the category — YC-backed, ~43k stars in five months, disciplined engineering, native mobile, daily ships. It contains zero first-party intelligence: no LLM call anywhere, no supervision, no auto-answer, no verification — and its hero "fan out five agents, merge the winner" marketing has no code behind it.

The layer Supercalm already occupies — measured supervision, verified completion, gated autonomous delivery — is exactly the layer their users are left to do by hand. The plan: prove that layer's reliability with named design partners, make it installable in minutes, and make it interoperable with any runner — including, potentially, Orca itself.

01What Orca actually is

Orca ("the AI orchestrator for 100x builders") is an MIT Electron app for macOS/Windows/Linux plus a native Expo mobile companion, from Stably AI (YC W22); founder Jinjing Liang is ex-Google Chrome. It runs 30+ CLI agents in parallel git worktrees. Verified in code:

  • Terminal engine — WebGL rendering, infinite splits, a background PTY daemon that survives app restarts and replays scrollback. Genuinely excellent.
  • Agent status — hooks-first via a loopback HTTP server with 14 bespoke per-CLI adapters, then OSC escape parsing, then title regex. States are a fixed enum: working | blocked | waiting | done. Notifications are templated title/body strings.
  • Orchestration — a SQLite bus (decision gates, worker mailboxes, federation between Orca instances) that a user-supplied coordinator agent drives with its own tokens. Orca ships plumbing; the thinking is outsourced to your foreground agent.
  • The hero claim is marketing — "fan one prompt across five agents, compare, merge the winner" has no fan-out primitive, no scoring, and no merge-of-winner in the code. The real workflow: create N worktrees by hand, eyeball diffs, gh pr merge.
  • Design Mode ("grab") — click an element in embedded Chromium and its sanitized HTML/CSS, cropped screenshot, and React source-file mapping land in the prompt. Novel and well-hardened.
  • Deep VCS/PM surface — GitHub (stacked PRs, in-app review) plus GitLab, Bitbucket, Gitea, Azure DevOps, Jira, Linear.
  • Mobile — full steering (PTY input, permission approvals, PR review) over LAN or an opt-in E2EE cloud relay. Their own findings doc records the relay UX as a bug farm: dead pages, grey-dot stalls, 5–12s pairing blackouts.
  • Voice — local STT dictation only (sherpa-onnx). No TTS, no assistant.
  • Engineering machine — 0.74 test-to-source ratio, 28 CI workflows, lint ratchets, perf budget gates. Never bet on them being unable to build something.

02The decisive fact, stated carefully

Orca makes zero first-party LLM calls. No model SDK in 2.7M lines; titles are 160-char truncations; attention is a four-value enum. Every "understand the fleet" capability — summarize, classify, answer, verify, judge, brief — is left to the user's own agent and tokens.

What this is not: a permanent ceiling. Adding a model call is a product decision away. The honest claim is narrower: today, nobody owns the supervision loop as a first-party, evaluated product. Supercalm's head start is real — supervisor brains, per-episode summaries, doctrine, an incident-replay lab, gated deploys — and the durable version of that lead is accumulated per-project policy, measured reliability (precision, abstention, escalation), and deploy-outcome evidence. Those take calendar time and real usage to copy — but only count if we accumulate and measure them.

They optimized the cockpit. We're building the autopilot — with the burden of proof that absorbed decisions are right.

05Strategy after adversarial review

Don't chase the cockpit. Editor, browser, six VCS UIs, WebGL terminals — their home turf, staffed and funded. Own the layer above, as an interoperable layer: supervision with measured reliability, riding existing runners instead of demanding replacement. The narrowed promise:

The promise
"Wake up to a reviewed queue of small, safely-landed changes — with the evidence, not a dashboard of terminals."

ICP for the next two quarters: technical solo founders and tiny teams already running Claude Code or Codex on web-app repos with scriptable tests and reversible deploys, on an always-on box. Teams, RBAC, enterprise, Windows: explicitly out of scope.

  • Make supervision provably reliable before making it louder — precision by prompt class, calibrated abstention, escalation correctness, prompt-injection resistance, and an autonomy ladder (observe → act-in-branch → merge-with-approval → allowlisted autodeploy → never-classes).
  • One golden onboarding path — macOS + launchd, one agent, localhost-only: a grounded "what needs you and what I'd answer" briefing on the user's own session within 10 minutes. No tailnet, no deploy credentials for first value. Metric: time to first trusted saved action.
  • Distribution = interop + design partners — a generic runner-hook protocol so Supercalm supervises sessions from any cockpit (an honest Orca-sidecar spike included); five named design partners recruited now; one public build-log artifact weekly. Their installed base is a channel, not only a threat.
Demoted by review
Judged fan-out — the earlier draft's flagship — was competitor-reactive, cost-multiplying, and its proposed benchmark was circular. It returns only when design partners demonstrably run competing attempts by hand and a blind benchmark beats trivial baselines.

06Execution plan — calendar cycles with gates

One externally observable outcome per cycle. WIP limit: one product bet + one reliability track + one distribution motion. Everything ships through the existing gated pipeline.

C0 Validation + threat model 2–3 wks · starts now
  • Recruit 5 named design partners from Claude Code/Codex power-user communities; watch them install today's product — their failures scope C1. Falsifiable question: for which recurring tasks will they accept exception-based review only?
  • Baseline supervision safety on existing lab + live history: auto-answer precision by class, false-done acceptance, escalation correctness. Encode never-classes (migrations, auth/billing, secrets, infra, destructive ops) as policy.
  • Prompt-injection red team: repo text is adversarial input to a system that acts. Lab scenarios + provenance rules.

Gate → baselines exist · ≥3 partners trialing · kill/continue thresholds agreed.

C1 One golden install + first trusted value 4–6 wks
  • macOS + launchd, one-line install; connect one existing claude/codex session; localhost-only; first-run ends at a real briefing of the user's own work in <10 min. Clean upgrade + uninstall. Linux only after outsiders finish the macOS path unassisted.
  • Fresh-install E2E extended to the full journey on a cold VM.

Metric → time-to-first-trusted-saved-action; install-to-activation conversion.

C2 The trusted supervisory loop, measured 4–6 wks
  • The evidence packet: blocker → grounded recommended reply with cited basis → approve-by-default (per-class opt-in to auto) → done-claim verified against acceptance criteria → PR/deploy packet → immutable audit ledger + weekly digest.
  • Reliability gates published per class; partner production deploys stay approval-required until their own data crosses thresholds.

Gate → ≥60% recommendations accepted · ≥3 partners weekly ×4 · ≥2 grant branch/PR authority.

C3 Runner interop = distribution 4–6 wks
  • Documented runner-hook protocol (claude/codex today; shape matches Orca's own adapters) — supervise sessions from any cockpit; honest Orca-sidecar spike.
  • GitHub as machine surface: evidence packets as checks/PR comments — policy-grade integration without building review UIs.
  • One distribution motion weekly: partner recruitment, public postmortem, or migration guide.
C4 Earned autonomy + demand-gated extras after C3 metrics
  • Widen auto-answer/deploy per class only where partner data crossed thresholds; publish the autonomy contract with at least one abstention and one blocked deploy on record — a system that always approves is not credible.
  • Fan-out returns only here, blind-benchmarked against test-pass-selection and single-flagship baselines, with a budget controller as precondition.
  • Voice stays a dogfooded output channel; promoted only if partner usage shows it beats push/text on decision latency.

Non-goals (hard fence)

Embedded editor · embedded browser/design-mode · VCS review UIs (machine integration is in-scope) · WebGL terminals · native mobile apps · Windows · enterprise — until C2–C3 gates are met with the narrow ICP.

Tripwires — business first, competitor second

  • Kill/continue: C1 activation <50% → rework onboarding before anything else. C2 acceptance <60% or any never-class violation live → freeze autonomy, fix the brain. No partner grants branch authority by C2 exit → the wedge is triage, not delivery; re-plan. Inference cost per supervised session above plausible willingness-to-pay → re-architect routing.
  • Competitor watch: stablyai/orca releases watched for first-party LLM calls, auto-answer/verify, or a real daemon mode → accelerate C2/C3, lean into interop + accumulated policy data. Strongest squeeze: platform vendors absorbing supervision into the agent itself — interop posture is the hedge.

07What the adversarial review changed

Two fleet critics (gpt-5.6-sol, code lens; gpt-5.6-terra, market lens) attacked the draft; both raw critiques are committed in the repo. Adopted: moat claim narrowed to "currently-unowned loop + measured head start"; fan-out demoted to demand-gated C4 (its benchmark was circular); sequencing inverted so supervision reliability precedes headline features; one ICP and one golden install path; design partners before packaging; autonomy ladder + injection threat model as C0 work; the interop/complement-Orca distribution posture (proposed independently by both critics); calendar-week estimates with WIP limits; LOC ratios kept as description, dropped as strategy; voice demoted pending usage evidence. Rejected/bounded: "a capable Orca user's coordinator can already do this" (the verified absence of any first-party judge stands — but we'll reproduce their coordinator workflow hands-on before public comparisons); dropping the autopilot frame entirely (it survives as internal shorthand behind the concrete promise); monetization planning now (deliberately deferred to C3 exit, logged as an open operator decision).
